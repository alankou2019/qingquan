# A电脑交接：薪酬数据权限自查与风险加固

## 本次处理

- 对薪酬敏感入口做了一轮自查，重点看了企业后台工资条查看确认、导出、统计报表、员工手机端本人薪酬和下属薪酬。
- 工资条“查看确认”页新增导出权限控制：
  - 只有超级管理员，或在“薪酬管理授权”中勾选“允许导出薪酬数据”的账号，才显示“导出确认结果”区域。
  - 直接访问 `/salary/payslipexport` 也会做同样权限校验，不能只靠前端隐藏按钮。
- 导出区域隐藏后，页面脚本增加空元素保护，避免无导出权限账号打开页面时报脚本错误。

## 已确认的安全边界

- 企业后台薪酬页面继续按 `company_id` 读取当前企业数据。
- 薪酬统计报表按“薪酬管理授权”控制部门和指定员工范围，导出仍要求 `can_export`。
- 员工手机端本人薪酬只读取已发放给本人的工资条。
- 员工手机端下属薪酬只读取授权部门或授权员工范围内的已发工资条。
- 手机端查看本人薪酬、确认工资条、查看下属薪酬已写入低敏操作日志，不记录工资金额明细。

## A电脑继续开发注意

1. 开发前先同步 GitHub 最新代码，再看本文件和上一份交接说明。
2. 不要提交生产配置、服务器密码、数据库密码、客户工资表、客户上传文件或日志。
3. 如果 A 电脑也改了 `SalaryController.php` 或 `payslipdetail.volt`，请先对比导出权限控制再继续。
4. 后续新增任何薪酬导出、批量查看、批量下载功能，都要同时做：
   - 企业隔离；
   - 薪酬授权范围；
   - 导出权限；
   - 低敏操作日志。

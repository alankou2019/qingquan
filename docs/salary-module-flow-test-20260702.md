## 发现的问题

### 1. 归档主表状态未同步

现象：

- 归档快照表 `salary_payroll_archives` 已成功新增 `2026-09` 归档记录。
- 但工资表主表 `payroll_periods` 中对应工资表没有同步标记为 `archived`。
- 本次测试中未看到 `payroll_archive` 操作日志。

影响：

- 企业后台“工资表核算”和“归档记录”的状态可能不一致。
- HR 可能误以为工资表还停留在审核通过状态。
- 后续恢复、报表统计和菜单按钮显示可能出现理解偏差。

建议：

- 修复归档动作，确保创建归档快照后，同步更新工资表主表状态和归档人、归档时间。
- 修复后补测归档日志 `payroll_archive`。

### 2. 恢复后的工资表状态不够准确

现象：

- 从归档记录恢复后，工资表状态变为 `rejected`。

影响：

- 业务上“恢复”是恢复到工资表核算重新核算，不是审核驳回。
- 使用 `rejected` 会让 HR 误解为审核人驳回。

建议：

- 恢复后状态改为更适合重新核算的状态，例如 `calculated`。
- 恢复时清理审核状态，但保留归档记录。

### 3. 员工端确认日志缺少工资月份

现象：

- 员工端查看本人薪酬日志有工资月份。
- 员工端确认工资条日志 `mobile_payslip_confirm` 的工资月份为空。

影响：

- 后续按月份追溯员工确认动作不方便。

建议：

- 员工确认前读取工资条明细，把工资月份写入确认日志。

## 本轮结论

薪酬模块第一版主流程已经基本跑通，但不建议直接上线生产。

上线前建议先修复以上 3 个问题，再做第二轮流程试测。

## 下一步建议

下一步建议开发“薪酬归档/恢复状态修复与员工确认日志补全”，修复后再重新跑一遍：

工资表核算 -> 提交审核 -> 审核通过 -> 归档 -> 从归档发工资条 -> 员工确认 -> 报表和日志核对。
